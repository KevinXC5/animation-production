# 声音、时间戳与节奏

本模块按需加载：无声作品全部跳过；音乐主导作品跳过 TTS；真人旁白直接做音频校对与对齐。语言、声线、字幕种类和停顿长度以当前作品为准。

**默认 TTS 为豆包语音**，接口与实测要点见 [doubao-tts.md](doubao-tts.md)，合成脚本为 `scripts/doubao_tts.py`。用户指定其他服务时按其文档接入，下面的通用规则同样适用。

## TTS 接入

接口以用户给定的当前文档为准。读取 `.env` 中指定的字段，例如 `APIKEY` 和 `VOICE`；代码仅记录字段是否存在，不输出值。秘钥只用于向用户指定服务鉴权，不带到动画前端、日志和分享包。

豆包双向流式的要点（完整内容见 doubao-tts.md）：

- 连接与会话的建立、发文本、结束会话、收完音频、结束连接应严格遵守协议。
- 音频与控制事件的消息类型不同；音频帧的会话 ID 长度字段也必须正确读取。
- `audio_params.enable_subtitle: true` 用于请求字幕。字级时间出现在 `TTSSubtitle`，并非 `TTSSentenceEnd`；实测为会话全局时间，多分句无需累加偏移。
- `additions` 按接口要求整体编码为 JSON 字符串。可包含 `explicit_language: "zh-cn"`、`context_texts`、`aigc_watermark: false`。音色/模型兼容性和参数位置须再核文档。
- `aigc_watermark: false` 指可选结尾节奏标识；不等于承诺关闭任何隐式元数据或平台标识。
- 先测普通句、带多个感叹号的句子和长句，确认实际语速、时间戳与解码时长。

合成重试用有限次数和退避；同一请求重试可能重复计费。鉴权错误或配额耗尽应停止，而不是无限重试。逐句成功后将音频、字幕与输入指纹原子落盘，避免全部完成前才写总索引。

## 时间戳不可盲目累加

不同接口可能返回整条音频绝对时间、句段相对时间、重复中间结果或重叠区间。

正确顺序：

1. 保存原始控制事件，确认时间单位、字幕所属句段、段偏移定义以及音频边界。
2. 若是句段局部时间，按明确的音频起始偏移平移；若已经是全局时间，不再累加。
3. 合并时剔除重复结果，核对文本覆盖、起止单调性、每段范围和音频实长。
4. 不能证明偏移时，抽查开头、中间、末尾的实际音画同步；仍不可靠则改句级字幕并披露。

不能仅用“下一段起点小于上一段终点”推导所有事件的偏移；也不能用上一字幕末尾代替下一音频段起点，忽略两者间停顿。

## 排布与裁切

每句至少记录原始时长、保留片段起止、字幕基准、时间线起点和输出发声终点。

- 可裁掉首尾过长静音，但保留自然起音和尾音；只根据末字时间戳裁切可能吞音。
- 若按发声终点推进下一句，却把整个原始 MP3 拼入音轨，未裁掉的尾部可能与下一句重叠。
- 音频裁切后，字幕按相同偏移调整。音频和字幕共同决定下一句起点。
- 字幕默认整句显示，时间取该句发声起止；字级时间戳只在用户要求逐字效果时用于渲染。
- 句间停顿按语气、信息密度和画面动作调整，不套统一数值；转场无需强制额外静音。
- 找不到关键词音效触发点必须报错或要求显式替代时间，不静默丢失。
- 两种语言过长时按意群拆字幕或换行，设安全区并检查最长字幕，不硬塞成一行。

## 音轨制作

推荐独立保存旁白、配乐、动作音效和最终混音。三轨统一采样率、长度和声道；补零或裁切须明确，不依赖广播运算“自动对齐”。

配乐可来自用户提供的音乐、授权曲库或原创程序化音乐。原创时先按作品情绪确定配器、调式和速度，再按旋律动机、问答乐句、段落转折设计，不用随机音符凑时长。

配乐闪避参考：人声活动时压低约 6–10dB，起音 50–100ms、释放 250–500ms。重点是台词清晰，不能机械套参数。闪避曲线、整体响度增益用不同变量存储，避免响度归一化时覆盖逐样本曲线。

在线分享可从约 -16 LUFS、真峰值不高于 -1 dBTP 起步。RMS 不是 LUFS；应使用 FFmpeg 的响度测量功能验证，并区分采样峰值与真峰值。AAC 编码后可能产生更高峰值，最终文件也需复查。

```bash
# 对最终文件测量响度与真峰值，不写出音频
ffmpeg -hide_banner -i final.mp4 -af ebur128=peak=true -f null -
```

数值检查覆盖：NaN/Inf、直流、削波、时长、声道、响度、头尾淡入淡出、音效位置。人工试听覆盖：台词可懂度、错读、句间停顿、音乐疲劳、音效是否惊吓、结尾是否突断。无法实际听到声音时，明确写“完成数值检查，未完成人工试听”。
