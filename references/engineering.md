# 工程与数据协议

## 环境和可移植性

先按 design.md 确定技术路线，引擎相关的依赖和注意事项见 [engines.md](engines.md)。通用工具：浏览器类引擎用 Node.js 配 puppeteer-core（需要另装 Chrome）逐帧出图；声音模块可用 Python 3、websockets、NumPy、SciPy；编码与媒体检查用 FFmpeg/ffprobe；Pillow 可用于拼图和图像结构检查。依赖按所选路线安装，不是全都必装。实际版本以项目锁文件和兼容性测试为准，不强制“最新版”。

已有 Node 工程优先 `npm ci`；新工程选择经过测试的一组版本，提交锁文件。Python 使用项目虚拟环境并记录依赖。检查系统工具是否在 PATH 上。不要假定某台机器的芯片型号、内存或渲染时间。

Chrome 路径、GPU 后端、字体路径、声音目录、输出目录、fps、分辨率和片长都应可配置。macOS 可测试默认后端或 Metal；不要在所有平台强制 Windows 的 D3D11。浏览器控制要通过当前宿主规定的工具；已有离线出帧工程也应按该环境的许可执行。

不能只凭图片判断作者使用了什么工具。画面质量取决于美术与表演设计，不取决于用了哪个库。

## 推荐布局

以下为带解说的代码动画参考布局，不是所有引擎的强制目录。无旁白时省略 TTS 与句子音频；三维项目增加模型、材质、灯光和仿真缓存；Blender、Remotion 等有自身工程结构的路线沿用其惯例，只保留时间线与输出的约定。时间线可以按镜头、节拍或动作组织。

- `BRIEF.md`：受众、内容边界、风格、画幅、语言、交付方式。
- `script/story.json`：待合成文案。
- `tools/`：TTS、时间线、配乐、混音工具。
- `audio/tts/`：分句音频、原始字幕事件、缓存清单。
- `audio/timeline.json`：音画统一的绝对时间轴。
- `audio/voice.wav`、`audio/music/bgm.wav`、`audio/music/sfx.wav`、`audio/mix.wav`。
- `anim/src/`：底座（时间、绘制或渲染、文字、镜头与调度）、道具、角色和各章或各镜头的场景文件，按所选引擎组织。
- `anim/src/` 中的时间线数据：从 `audio/timeline.json` 自动生成，禁止手改。
- `anim/STORYBOARD.md`、`anim/ANIMATION_GUIDE.md`：分镜与接口契约。
- `anim/out/<版本>/frames/`：逐帧图、日志、版本清单；最终 MP4 与验收报告。

## 剧本字段

以下为数据形状示例，不是完整可直接出片的工程：

```json
{
  "title": {"cn": "作品名称", "en": "Title"},
  "tone_default": "表达自然，发音清晰，语气符合当前作品。",
  "chapters": [{
    "id": "c0_intro",
    "name": "开场",
    "lead_in": 0.6,
    "tail": 0.5,
    "lines": [{
      "cn": "第一句旁白。",
      "en": "The first line.",
      "tone": "本句语气",
      "sfx": [{"name": "chime", "at": "第一", "nth": 1}]
    }]
  }]
}
```

建议每句有稳定 ID，避免插入一句后造成所有文件名对应关系改变。若沿用“章节 ID + 顺序号”，必须用输入指纹判定缓存，不能只看文件名。

## 时间线字段

附带检查脚本接受以下结构；所有时间为全片绝对秒数：

```json
{
  "duration": 3.0,
  "chapters": [{"id": "c0_intro", "name": "开场", "start": 0.0, "end": 3.0}],
  "lines": [{
    "id": "c0_intro_01", "ch": "c0_intro",
    "cn": "你好！", "en": "Hello!",
    "start": 0.6, "end": 1.6,
    "words": [{"w": "你", "s": 0.6, "e": 1.0}, {"w": "好！", "s": 1.0, "e": 1.6}]
  }],
  "sfx": [{"name": "chime", "t": 0.6, "line": "c0_intro_01"}]
}
```

`duration` 来自主时间线，并与需要的声音或仿真长度一致。单语句子可用 `text` 替代 `cn/en`；中英双语是兼容字段，检查时加 `--require-bilingual` 才强制双语。无旁白作品允许 `lines: []`。章节可以代表场景或循环片段，仍需覆盖全时长。

`words` 用于校验字幕覆盖和确定发声边界，整句字幕渲染只用 `start/end`。`words` 允许显式降级为空，此时不能提供逐字高亮。英文分词或中文带标点时都要保留原始字幕内容，避免丢字。其他语言可用 `text` 配合项目自己的翻译结构；附带检查器只核对原文覆盖，不解释自定义翻译字段。

## 底座设计

以下原则适用于任何引擎，具体实现见 [engines.md](engines.md)。

1. **时间确定性**：画面只由时刻 `t` 决定，例如 `frame(t)` 纯函数、`seek(t)` 或引擎自身的帧号驱动，不依赖实时时钟或上一帧残留状态。测试同一时刻分别在新页面、顺序渲染和乱序渲染的结果是否一致。
2. **随机可复现**：随机数、噪声和粒子使用固定种子；物理仿真用固定步长并烘焙缓存。
3. **配置集中**：尺寸、fps、曝光频率、字体、调色板、章节与资源由配置文件定义。底座不绑定具体作品的标题、角色或风格。
4. **表现手法封装**：绘制或渲染层按当前风格封装所需手法（平涂、渐变、笔刷、材质、光影等）；高开销效果是性能测试对象，不把固定数量上限当普遍定律。
5. **屏幕层与场景层分离**：镜头变换只作用于场景；字幕和界面文字位于屏幕层，不跟随镜头和角色局部变换；场景内的道具文字需显式做坐标转换。
6. **角色一致**：角色用可识别的剪影、统一比例、表情与完整动作姿态；重复的小幅摆动不能代替表演。
7. **资源就绪再出帧**：字体、图片、模型、纹理全部加载完成后才开始渲染第一帧，避免首帧缺字、缺图。

## 缓存依赖

- TTS 指纹：文本、语气、音色、模型、语速、语言、采样率、影响输出的请求参数与客户端版本。
- 时间线指纹：所有有效音频、字幕边界、间隔策略、首尾保留量、音效标记。
- 帧指纹：时间线、所有绘制代码、字体、图片、依赖锁、尺寸、fps、随机种子配置。
- 混音指纹：时间线、三轨内容、闪避和响度参数。
- MP4 指纹：帧清单、混音、编码设置。

上游发生变化，重建相关下游；不要把旧帧按“存在且大于 1000 字节”直接视为新版本有效产物。缓存按版本隔离，先报告旧产物再决定删除。
