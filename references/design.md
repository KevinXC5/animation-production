# 技术选型与视觉、运动设计

## 从选题推导技术路线

引擎由作品需要的画面决定，技能不预设默认框架。按以下顺序判断：

1. **拆画面特征**：从选题、参考和交付要求中找出决定性的特征，例如笔触与材质、空间纵深、光影、镜头运动、角色表演、数据或公式、真实界面、实拍素材、透明输出、画幅与时长。
2. **推导候选路线**：找出能直接表达这些特征的工具。画面同时需要多种特征时可以混合，例如三维场景叠加二维手绘层、界面动效叠加实拍素材，最后统一合成。
3. **权衡代价**：比较学习与实现成本、渲染速度、逐帧确定性、依赖与许可、后续修改难度，以及当前环境能否跑通。
4. **最小样片验证**：用几秒样片打通“出帧 → 编码 → 播放”全链路，确认关键画面特征能实现后再全面制作。样片达不到目标时换路线，不靠堆效果硬撑。
5. **记录理由**：在 `BRIEF.md` 写明选用的路线、理由和放弃的备选，便于后续续做和复查。

下表只是常见对应关系，不是完整清单。表中没有的工具（如 GSAP、Lottie、Pixi.js、Babylon.js、Godot、After Effects 脚本等）只要能按时间精确出帧、可复现导出，同样可以选用。

| 画面特征 | 常见路线 | 先验证什么 |
|---|---|---|
| 绘画、版画、水彩、线描、生成艺术等二维笔触 | p5.js、p5.brush、Canvas 2D | 笔刷与填色、字体、图层顺序、曝光、离线出帧性能 |
| 品牌动效、排版、信息卡、界面和产品演示 | SVG/Canvas 配 GSAP、React + Remotion、现有组件配时间控制 | 真组件与字体、逐帧确定性、布局、视频导出与相关工具许可 |
| 三维物体、空间镜头、粒子、光影材质 | Three.js、Blender 或现有三维工程 | 模型/材质/灯光、相机、抗锯齿、物理缓存、输出色彩与透明度 |
| 数学、算法、几何推演 | Manim 或自建几何动画 | 公式字体、符号布局、解释步骤和镜头可读性 |
| 逐帧手绘、骨骼角色表演 | 可编辑角色资产、专门动画工具或 Canvas 姿态绘制 | 关键姿态、过渡、视线、口型、角色一致性 |
| 照片/视频混合、拼贴、画面合成 | FFmpeg、合成工具配绘制层 | 素材授权、遮罩、跟踪、帧率、色彩和编码 |
| 文生视频/图生视频镜头 | 用户明确授权的服务，再剪辑合成 | 可用接口、预算、上传范围、角色一致性、生成长度与编辑能力 |

以上是选型参考，不表示技能已安装这些依赖或拥有相应服务。先检查当前工程与环境，不在无依据时承诺任何引擎“效果一定更好”。选定后读取 [引擎落地要点](engines.md) 中对应小节；混合路线分别读取相关小节。

已有成熟工程时优先复用。若更换引擎才能达到目标，解释具体理由：例如原生三维灯光、逐帧手绘控制、真实界面组件，而不是笼统地说某库“没有动画基因”。

## 视觉参考拆解

分别记录：
1. 形状语言：硬边、软形、线条粗细、轮廓与负空间。
2. 色彩：主色、强调色、明度分层、饱和度及节奏变化。
3. 材质：纸、墨、水彩、玻璃、金属、像素、黏土等。
4. 空间：平面、层叠景深、透视、灯光、阴影、镜头焦段。
5. 排版：字体、字重、层级、阅读时间与平台安全区。
6. 动态：速度曲线、停顿、曝光、镜头运动、转场和音画关系。

设计输出包括代表性静帧、角色/物体状态表与运动样片。参考图里“少”不等于粗糙；有节制的线条和构图可以比细节堆砌更有表现力。

## 运动的验收标准

- 观众能看懂动作起因、目标与结果。
- 重量与惯性合理：启动前准备、接触后反馈、跟随动作逐渐收束。
- 镜头运动不把关键信息甩到画外，也不让字幕和背景不必要地晃动。
- 重复周期不机械：用于呼吸或云层时幅度有限，不让所有元素同频摆动。
- 转场服务内容关系：匹配剪辑、遮挡转场、推拉或硬切有目的，不给所有章节套同一种转场。
- 有限曝光、轮廓抖动等手绘手法只用于需要它的风格。
- 循环片检查第一帧与虚拟周期末帧，以及位置、速度、材质和光照连续性；不要重复首帧导致停顿。

## 信息和声音的关系

旁白主导：解说先定时，再安排动作与阅读时长。
音乐主导：分析节拍、强拍、段落和高潮；不是所有物体都必须每拍弹跳。
无声主导：通过运动和构图讲清楚，不假定有旁白补充缺失信息。
交互预览：交互状态与最终离线时间线分开，避免鼠标、窗口焦点和网络时延改变成片。

## 风格与合规

适龄限制只在受众需要时启用，不把所有作品做成儿童卡通。科普与历史内容核对事实；品牌与产品内容核对真实功能。生成或改编内容不能掩盖来源和授权问题。字幕、配音和画面里的语言取决于发布对象，可中文、英文、多语或无文字。
