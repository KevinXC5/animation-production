# 渲染、续跑与交付验收

## 先验证再渲染

依次输出：静帧 → 角色或物体/场景拼图 → 5–10 秒样片（有声音要求时带声音）→ 各镜头关键帧 → 全片。循环动画先验一整周期；三维额外检查抗锯齿、光照和仿真缓存。

图片生成后使用可读取图像的工具真正查看。`open` 打开系统预览、不为空的文件、采样某个像素都不等于视觉审阅。静帧也不能证明运动连贯或声音好听。

应检查：
- 人物是否一眼可识别，比例、服装、表情是否一致。
- 动作是否有准备、作用、反馈；箭是否朝目标飞，撞击是否在画面与声音同一时刻。
- 画面有明确重点和有意留白，而不是空背景配一个小人。
- 字幕完整、不溢出、不挡主体；逐字高亮不冒充音素对齐。
- 水彩图层、文字与镜头转换没有错误；角色临时进入画外须是有意安排。
- 章节交界的笔刷遮罩本身是设计效果，不应仅因截到转场就判为故障。
- 结尾淡出完整，没有只因音轨较短而提前截断。

## 性能与并发

在多个不同复杂度场景取样测量，区分首帧初始化、单帧延迟和多 worker 总吞吐。并发页面会共享 GPU、内存和编码资源；从 1–2 个开始测试，逐步提高，吞吐下降或内存增长就回退。

预期帧数为 `ceil(duration * fps)`。估时用实测的**有效毫秒/帧 × 尚未完成帧数**，并报告这只是估计。没有硬件与运行记录，不填写“某芯片耗时多少”或“耗费多少工时”。

## 长任务生命周期

执行工具的等待上限与操作系统进程生命周期不同。若 Bash 工具提供 `timeout`，600000ms 可能是该工具的最大等待值，不是操作系统、Node 或 FFmpeg 的普遍限制，也不一定是默认值。

优先使用宿主支持的可追踪后台任务。其完成通知可用时等待通知，不反复短间隔轮询。只有普通 shell 可用时，可采用以下示例；它假设项目**已实现** `render.mjs --frames`，并且已经核准命令、路径及输出版本：

```bash
# 当前目录应为经过确认的动画工程；RUN 使用每次唯一的版本目录
RUN="$(pwd)/out/render-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$RUN"
# 范围参数和输出帧目录必须先按实际渲染器验证；此处命令仅作示例
nohup sh -c '
  node render.mjs --frames=0:999 --workers=2
  code=$?
  printf "%s\n" "$code" > "$1/exit-code"
  exit "$code"
' sh "$RUN" > "$RUN/render.log" 2>&1 < /dev/null &
printf "%s\n" "$!" > "$RUN/render.pid"
```

`0:999` 只是旧案例中覆盖小于 999 秒视频的写法，不是通用“全片”选项。新渲染器推荐提供 `--all` 或精确的帧号范围，固定输出到该版本目录；结束索引采用排他语义，覆盖 `[0, ceil(duration*fps))`。

`nohup` 主要避免挂断信号影响，不保证进程不被宿主清理、资源限制或内存不足终止。启动后检查 PID 和首批有效帧；完成时检查退出码和帧清单。不要承诺后台任务自动编码，除非已经配置并验证后续步骤。

遇到超时应先检查存活进程、已写帧和退出信息，不直接重启整片；退出码 137 是强制终止信号的线索，不凭这一项认定必然内存不足。不要结束其他项目的 Chrome/Node 进程。

## 输入版本与完整性

每次出帧记录：源码与字体/资源指纹、时间线指纹、依赖锁、尺寸、fps、帧区间、渲染开始结束与退出码。

续渲只复用版本匹配、能解码、尺寸正确的帧。输入变化后选择新输出目录，或明确列出受影响帧再清理；共享底座改变通常影响所有帧。

编码前检查：
1. 帧名固定格式，例如 `f00000.jpg`，从 0 连续到最后一帧。
2. 文件数与预期一致，无缺失或多余旧帧。
3. 所有图像可解码、尺寸一致，帧率与时间线配置一致。
4. 有声音要求时混音必须存在、完整、长度正确，缺混音应阻断；明确无声交付则不强制存在音轨。透明输出检查 alpha 通道和目标软件兼容性，不用 yuv420p MP4 冒充透明素材。

附带 `check_delivery.py` 检查编号和文件非空；图像解码与视觉内容应另行验证。

## 编码与媒体核对

常用参数：H.264 `libx264`、CRF 18–20、`yuv420p`、AAC 192k、`+faststart`。分辨率需满足编码器要求。输入序列帧率与渲染帧率必须相同，不能用输出 `-r` 掩盖重复或缺失。

FFmpeg 子进程必须处理启动失败和非零退出码，用 `finally` 关闭浏览器与管道。日志出现“已写出”或文件大小正常都不能代替退出状态。

`-shortest` 可能掩盖短音频或短视频造成的截断，不能代替时长验收。

```bash
# 基础信息
ffprobe -v error -show_streams -show_format -of json final.mp4

# 完整解码验证（返回非零或有错误输出应调查）
ffmpeg -v error -xerror -i final.mp4 -f null -
```

最终视频时长允许帧量化和编码延迟范围内的微小偏差，通常在一两帧附近；偏差较大须定位，不能只放宽阈值。字幕是烧录还是可关闭的独立字幕轨应在交付中说明。

## 验收记录模板

- 成片绝对路径、容器/视频/音频编码、尺寸、fps、时长、文件大小。
- 期望帧数、实际帧数、缺失帧、版本匹配结果。
- 时间线校验与整片解码结果。
- 已查看的关键帧/转场区间，已播放或试听的片段。
- 响度、真峰值和混音清晰度检查；数值与听感分列。
- 未确认项、降级项、素材来源与许可位置。
- 从工程重跑的明确命令，不把旧的失败文件列为最终成果。
